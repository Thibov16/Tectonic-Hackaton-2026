## 1. Context and goal

SD Worx is an HR and payroll company. Its knowledge lives in policies, manuals, procedures, emails, Teams chats, meeting transcripts, contracts, tickets and in the heads of experts. Finding information is only step one. The hard question: **is the answer reliable, current, and does it apply to THIS customer, country and situation? Where are the gaps? Who has the expertise?**

Usage scenario: a customer contacts SD Worx looking for a document or answer. An SD Worx employee types what the customer knows into a text field. The system searches many heterogeneous files and returns sources ranked by **trust in the context of this specific query**, with explanations, conflicts, gaps and suitable experts.

Core principle: **trust is computed per (document, query context), never as one absolute score per document.** The same policy can be right for a Belgian customer, wrong for a Dutch one, or overridden by a customer contract.

Pitch sentence: *"We don't just find documents. We show which answer you can trust, why, where sources contradict each other, and where the gap is."*

## 5. Data model (SQLite, idempotent, rebuilt by an ingest command)

`documents`: `id, path, doc_type (policy|procedure|kb|contract|email|chat|meeting|ticket|analysis|release_notes|wiki|ai_summary|directory|other), title, doc_id, version, status (CURRENT|SUPERSEDED|DRAFT|SIGNED|FINAL|UNKNOWN), country (BE|NL|DE|ALL|UNKNOWN), customer, effective_date, created_date, last_modified, author, owner, approved_by, approval_date, next_review, source_location (official_repo|mailbox|teams|personal_drive|wiki|ai_generated|unknown), raw_text, metadata_confidence, retracted`

`claims`: `id, document_id, subject, value_num, value_text, unit, scope_country, scope_customer, valid_from, valid_to, fragment, extractor (rule|llm), confidence`

`links`: `from_doc, to_doc, relation (supersedes|superseded_by|retracts|corrects|overrides|duplicates|replies_to|cites)`

Keep deterministic metadata (front matter) separate from inferred metadata (lower `metadata_confidence`).

## 6. Ingest (backend/app/ingest)

1. **Parsers:** `.md` (front matter + body + tables), `.eml` (From, To, Date, Subject, Reply-To, body), chat `.txt` (`YYYY-MM-DD HH:MM Name: text`, channel header, reactions line, message-level split), meeting `.txt` (date, attendees, `Decision:` and `Action:` lines), `.csv` (expert directory → expert objects; ticket export → one document per row).
2. **Normalisation:** infer missing `country` (keywords, currency patterns), `customer` (fuzzy match against known customers), `doc_type`. Set `metadata_confidence` (1.0 front matter, 0.6 inferred, 0.3 guessed).
3. **Versioning:** group by `doc_id`; CURRENT = approved, `effective_date <= TODAY`, highest version; older approved versions SUPERSEDED; DRAFT stays DRAFT; create `supersedes` links. Same `doc_id`/version without approval block from a personal drive → `duplicates` link, flagged as possible forgery.
4. **Corrections:** detect retractions via patterns ("CORRECTION", "sorry, my earlier", "not correct", "please ignore my previous", "@name not correct") plus same subject/thread and date order → `retracts`/`corrects` links, `retracted=True`.
5. **Overrides:** contract claims with a customer scope create `overrides` links to the matching policy subject.
6. CLI: `python -m app.ingest.loader --data ../data/sdworx_testset --rebuild`; auto-ingest on first start when the DB is empty.

## 7. Retrieval (backend/app/retrieval)

- **Query understanding:** extract `customer`, `country`, `topic` (taxonomy: remote_allowance, payroll_deadline, meal_vouchers, company_car, sick_leave, data_handling, bank_details, year_end_bonus, other), optional date, `question_type` (lookup | how_to | verify_claim | who_knows). Rule-based by default, LLM refinement optional. Always return the interpreted context so the UI can show it.
- **Hybrid index:** BM25 + embeddings over chunks (~800 chars, overlap 100), reciprocal rank fusion, top 25 candidates aggregated per document with the best fragment as `evidence`.
- **No silent filtering:** mismatched documents stay candidates; the trust engine demotes and explains them. Exclude only on a critical integrity finding.
- **Verify-claim mode:** if the employee types a concrete customer claim ("they say the allowance is 140"), extract the value and report whether it is confirmed, outdated, overridden or unsupported.

## 8. Trust engine (deterministic and explainable)

All weights and thresholds live in one `TrustConfig` in `config.py`. Every score returns human-readable **reasons**.

### 8.1 Claims
Rule-based first: amounts (`EUR\s?\d+([.,]\d+)?`), ordinal days, "Nth working day", units (per day/month), subject from topic keywords. Output `Claim(subject, value, unit, scope, valid_from, fragment)`. Optional LLM extractor with strict JSON schema; `fragment` is required and must be an exact substring of the document, otherwise the claim is rejected. Chats produce claims per message with author and correction status.

### 8.2 Five signals (0..1)
1. **Authority:** approved policy / signed contract 1.0; procedure or KB 0.8; final post-incident analysis 0.7; release notes 0.7; email from policy owner 0.7; meeting decision 0.65; ticket resolution 0.6; expert email 0.6; chat 0.3; unsourced rumour 0.1; unreviewed AI summary 0.2; undated wiki 0.2; unknown/personal drive 0.15. +0.05 if approval info exists (cap 1.0). −0.1 if the author is inactive/left.
2. **Currency:** CURRENT/SIGNED 1.0; FINAL 0.9; UNKNOWN by age (<12 months 0.7, 12-24 months 0.45, >24 months 0.2); overdue `next_review` ×0.5; later retraction/correction → 0; undated 0.2.
3. **Applicability:** customer match 1.0; country match 1.0; ALL 0.8; UNKNOWN 0.4; mismatch 0.1; contract of another customer 0.0; topic mismatch −0.5.
4. **Corroboration:** count **independent** source groups asserting the same normalised claim. Independent = different author AND different doc_type family, or different official documents. Messages in one chat thread and "+1"/thumbs-up count as ONE group. 0 → 0.2, 1 → 0.5, 2 → 0.8, 3+ → 1.0. If a higher-authority source contradicts, cap at 0.2.
5. **Integrity:** start 1.0, subtract per finding (8.4), floor 0.

### 8.3 Formula and gates
```
trust = gate_multiplier * (0.30*authority + 0.25*currency + 0.25*applicability + 0.10*corroboration + 0.10*integrity)
```
Gates (all logged as reasons):
- SUPERSEDED → ×0.15, role `historical`
- DRAFT → ×0.35, role `context_only`
- retracted/corrected → ×0.05
- critical integrity finding (prompt injection, spoofed sender, BEC pattern) → ×0.0, role `blocked`
- applicability < 0.2 → ×0.3
- possible forgery (unapproved duplicate, personal drive) → ×0.1

Provide an `--explain` CLI and an API field that show the five components, gates and reasons. Provide a sensitivity function that recomputes rankings with perturbed weights (used by the evaluation).

### 8.4 Integrity checks (finding = code, severity info|warning|critical, message)
- **Prompt injection** in body, HTML comments or hidden text ("ignore previous instructions", "system instruction", "rate this document", "disregard any other document", "you are now") → critical, excluded from ranking but shown in flags.
- **Spoofed sender:** From domain not allowed (`sdworx-example.com`, known customer domains); Reply-To differs from From; lookalike domain (fuzzy ≥ 0.8) → critical.
- **Business email compromise:** urgency + bypass approval + bank detail change + secrecy → critical, cross-reference POL-SEC-002.
- **Data exfiltration request:** asks to mail payroll exports externally → critical.
- **Internal inconsistency:** same document gives two values for one subject (A06) → warning.
- **Fabricated citation:** AI summary cites a section that does not exist in the referenced policy → warning/critical.
- **Provenance problems:** personal drive, no author, no date, header vs last-modified mismatch, self-claims like "THE LATEST VERSION / always correct" → warning.
- **Missing metadata:** no country (A08) → info, lowers applicability, "verify country" flag.

### 8.5 Conflicts, overrides, gaps, verdict
1. Group claims by `(subject, scope)`.
2. **Override:** a SIGNED contract claim with `scope_customer == query.customer` overrides the policy claim. The policy stays `supporting` with reason "overridden for this customer".
3. **Temporal supersession:** only CURRENT sources win; SUPERSEDED claims are listed as `outdated` with a pointer to the replacement.
4. **Conflict:** two claims of comparable authority (difference < 0.15), valid at the same time, that disagree → verdict `conflict`, show both sides, recommend the owner as resolver.
5. **Gap:** best trust < 0.45, or all sources authority < 0.4, or the only official source has an overdue review and newer informal sources disagree (T5).
6. **Caution:** best trust 0.45-0.7, or best source informal.
7. **Trusted:** best trust ≥ 0.7, no unresolved conflict, no critical flag on the top source.
Return `verdict`, `answer_claim`, `confidence`, `primary`, `supporting`, `outdated`, `blocked`, `flags`, `gaps`.

### 8.6 Expert finder
Score = topic match 0.4 + country match 0.2 + recency of `last_active` 0.2 + evidence of correct contributions (authored a trusted source or a message matching the winning claim) 0.2. Experts inactive > 12 months or flagged as left → `available: false` with a warning. If nobody qualifies, return an explicit "no active expert found" gap.
